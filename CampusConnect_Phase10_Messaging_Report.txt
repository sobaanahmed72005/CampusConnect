5. DATABASE SCHEMA CHANGES
   - Created Table `marketplace_conversations`:
     * id (UUID PRIMARY KEY)
     * listing_id (UUID REFERENCES marketplace_listings(id) ON DELETE CASCADE)
     * buyer_id (UUID REFERENCES users(id) ON DELETE CASCADE)
     * seller_id (UUID REFERENCES users(id) ON DELETE CASCADE)
     * created_at (TIMESTAMP DEFAULT NOW())
     * updated_at (TIMESTAMP DEFAULT NOW())
     * CONSTRAINT uq_conversation_listing_buyer UNIQUE (listing_id, buyer_id)
   - Created Table `marketplace_messages`:
     * id (UUID PRIMARY KEY)
     * conversation_id (UUID REFERENCES marketplace_conversations(id) ON DELETE CASCADE)
     * sender_id (UUID REFERENCES users(id) ON DELETE CASCADE)
     * content (TEXT NOT NULL)
     * is_read (BOOLEAN DEFAULT FALSE)
     * created_at (TIMESTAMP DEFAULT NOW())
   - Created Performance Indexes:
     * idx_conversations_buyer (buyer_id)
     * idx_conversations_seller (seller_id)
     * idx_messages_conversation (conversation_id, created_at ASC)

6. REST API ADDITIONS
   - POST /api/messages/conversations: Initiate or retrieve listing conversation (Rejects self-messaging with 400).
   - GET /api/messages/conversations: Retrieve student's active buyer & seller conversations with last message & unread badge counters.
   - GET /api/messages/conversations/:id/messages: Fetch conversation message history (Enforces participant check: returns 403 for non-participants).
   - POST /api/messages/conversations/:id/messages: Send message via REST fallback (Enforces content validation: 1-2000 chars & participant check).
   - PUT /api/messages/conversations/:id/read: Mark conversation messages as read for non-senders.

7. SOCKET EVENTS
   - Server Connection Handler: io.use(socketAuthMiddleware)
   - Event `join_conversation`: Validates conversation_id UUID & participant authorization before joining room `conversation:<id>`.
   - Event `send_message`: Persists message to PostgreSQL, updates conversation updated_at, and emits `receive_message` payload to room `conversation:<id>`.
   - Event `typing` / `stop_typing`: Broadcasts real-time typing state to room `conversation:<id>`.
   - Event `disconnect`: Cleans up socket room connections.

8. AUTHENTICATION MECHANISM
   - Socket handshake validates HttpOnly JWT cookie or Bearer token (`jwt.verify(token, JWT_SECRET)`).
   - Executes per-request DB check (`SELECT id, is_active, session_version FROM users WHERE id = $1 AND is_active = true`).
   - Rejects unauthenticated connections immediately (`Authentication failed`).

9. AUTHORIZATION MODEL
   - Participant Authorization Boundary: Only `buyer_id` or `seller_id` associated with a `conversation_id` can join room `conversation:<id>` or access message history.
   - Self-Messaging Guard: Buyers are strictly prevented from initiating conversations on their own marketplace listings (returns 400 Bad Request).
   - Non-Participant Rejection: Requests by third-party students return 403 Forbidden.

10. SECURITY CONTROLS
    - Anti-CSRF Protection: REST mutation endpoints protected by double-submit XSRF-TOKEN verification.
    - Parameterized Queries: 100% of SQL queries use parameter placeholders ($1, $2) to eliminate SQL injection.
    - Output Sanitization: React automatic JSX escaping prevents XSS vulnerabilities in message feeds.

11. RATE LIMITING
    - Socket message dispatches and REST endpoints governed by sliding-window rate limiters preventing message flooding.
